# Code of Conduct

Benchhand is an engineering project. Disagreement is expected. Disrespect is not required for the disagreement to be technically correct.

## Be useful to work with

Participants are expected to:

- discuss ideas and code without attacking people;
- make technical criticism specific enough to act on;
- distinguish evidence from preference;
- admit uncertainty when evidence is incomplete;
- give newcomers room to learn without lowering the project’s technical standards;
- respect privacy and coordinated vulnerability disclosure;
- avoid harassment, discrimination, threats, or deliberate disruption.

## Review behavior

Strong review is welcome.

“This can corrupt a file if rename fails here, and this test reproduces it” is excellent review.

“This is bad” is mostly a mood.

Review the behavior, contract, evidence, maintainability, and user impact. Do not use code review as a competitive sport.

## Maintainer action

Maintainers may edit, hide, lock, or remove project interactions that violate these expectations, and may restrict participation when necessary to protect contributors or the project.

Serious safety or conduct concerns should be raised privately whenever public discussion would expose sensitive personal or security information.

## A final practical rule

Assume good intent once.

After that, use evidence.
